# 新加坡降雨项目：方法说明、研究逻辑与结果解读


## 1. 我们真正要回答的问题

本项目使用 data.gov.sg 的 Historical Rainfall across Singapore 集合中 **2017 至 2024 共八个年度文件**。一个分析单位是一个监测站在一个五分钟时点的降雨记录，而不是“一天”或“一场暴雨”。所有日历变量统一使用 **Asia/Singapore（UTC+8）**。

任务 1 分别回答：一年内哪个月份较湿、一天中哪个时段较容易下雨、不同年份的降雨量和湿时段比例如何变化，以及监测站覆盖变化会不会造成假趋势。任务 2 输出

\[
P(Y_{s,t}>q\mid\mathcal I_t),\qquad
Y_{s,t}=\sum_{j=1}^{6}r_{s,t+5j\text{ min}},\quad q\ge0.
\]

其中 `s` 是监测站，`t` 是发出预测的时间，`q` 是用户输入的毫米阈值，`I_t` 是在 `t` 时真正可获得的信息。**“more than” 使用严格大于 `>`**，例如目标恰好为 5 mm，不属于“超过 5 mm”。`q=0` 对应接下来半小时是否有雨。实际研究阈值使用非负数；若程序收到有限负阈值，由于有效雨量非负，可直接得到概率 1。

模型 A 使用近期雨量做短临预测；模型 B 仅依赖站点、位置和周期时间，提供未来日期的历史日历风险。两种模式的完整说明见 `docs/TASK2_CALENDAR_RISK.md`。以下历史窗口说明适用于 A：用户只需要输入站点、时间和阈值，程序负责从历史观测表提取特征。它不是仅凭三个参数就能对任意遥远未来天气作准确预测。历史特征不完整时，不应悄悄补成晴天或输出貌似正常的概率；应返回明确的不可评分状态。归档数据中的更新时间有助于回放信息可用性，但无法完全重建真实 API 发布延迟、事后修订和现场数据接入条件，因此必须保留这个限制。

## 2. 为什么数据清洗不能只是 `dropna()`

官方集合说明时间使用 SGT，并明确提示数据可能缺失、没有经过正式气候数据的同等质量控制。因此，缺记录、设备换址、时间错误和重复记录都可能改变结论。[1]

### 2.1 可追溯的读取

下载器按固定的八个 dataset ID 下载年度 CSV，记录来源、年度、下载状态、文件大小与校验信息。保留原始文件，再使用 Spark 将有效记录写成列式 Parquet。所有年度使用同一规范字段，不依赖 Spark 对某一小段 CSV 的偶然类型推断。字符串先清理空白，再显式解析站点、观测时间、降雨量、经纬度和更新时间；保留来源信息用于追查异常。

官方字段 `reading_type` 为 `TB1 Rainfall 5 Minute Total F`，单位为 `mm`；本实现把它解释为五分钟区间雨量，而不是从某个起点持续累计的仪表读数。清洗代码另外接受测试夹具中的 `rainfall` 类型标记。**目录没有明确说明时间戳是否严格代表仪器区间终点**；本项目假设它表示截至该时间的区间，并将目标操作性定义为未来六个标记格点。应记录这一假设，获得更完整的仪器说明后复核实际预测区间。

### 2.2 清洗规则及理由

| 检查 | 处理 | 为什么这样做 |
|---|---|---|
| 时间和年度范围 | 显式设置 SGT；保留 2017-01-01 至 2025-01-01 前的观测 | 防止 UTC 转换后误分到前一天、前一个月或前一年 |
| 五分钟时间格点 | 只允许距离最近五分钟格点不超过 2 秒的记录归一化；保留原始时间和偏移审计 | 某些时间格式可能位于 `:59`；不能用不受限四舍五入把真实不规则采样伪造成正常观测 |
| 无效数值 | 空值、无法解析、NaN、无穷值、负雨量隔离；经纬度异常单独记录 | 负雨量不是物理观测；类型错误不能默默变成 0 |
| 重复站点—格点 | 完全相同的记录折叠；同一格点不同降雨值作为冲突隔离并计数；同一有效站点格点若另有无效源行，也保守隔离 | 求和会重复计雨；随便选一条会掩盖数据冲突 |
| 大雨量核查 | 保留有效非负观测，输出正值分位数、对数频数、最大值和 top-100 记录及邻近观测供核查；不设固定 50 mm 阈值 | 暴雨是预测目标；无依据删极值会美化误差、削弱模型 |
| 缺失格点 | 缺失保留为缺失，不插值成雨量、不补零 | 缺失不等于没有下雨；未来标签缺失会形成错误负样本 |
| 站点元数据 | 使用 station ID 作为身份；检查站名和坐标变化 | 名称可能修改；空间变化需要在方法说明中解释 |

详细最终计数由 `quality` CSV 输出。报告应列出原始记录数、有效记录数、无效时间/雨量数、重复数、冲突数、调整格点数和可用于预测的样本数。各项质量标记可能重叠，不能把它们全部简单相加后声称等于删除总数；删除率应由明确的前后记录数计算。

### 2.3 覆盖率与观测网络

月覆盖率 = 有效唯一五分钟记录数 /（288 × 该月日数）。日历骨架保留全部96年月组合和无记录站点月份：记录计数为0，雨量仍为缺失，不填成0。

原始时间戳与清洗后的格点时间戳可能在午夜附近跨日期，因此逐日记录数差异不能全部解释为删除；需要核对总数并保留原始/清洗两列。

## 3. Task 1：全年月分析（v5）

- 数据探索包括记录规模、站点数量、零雨比例、正雨量分布与分位数、源文件缺口和覆盖率。
- 每个年月独立使用覆盖≥90%的站点，研究月度、季节、小时和合格日分布；不再让八年共同站点交集限制主要分析。
- 逐年变化既展示可用合格站点描述，也针对具体年份对按相同站点/月份配对；位置跨度和配对平均坐标差按0.005度筛查。配对差异不是面积平均或显著性检验。
- 年累计要求全年≥95%且每月≥90%，计算站点完整日历年观测累计量及站点均值，不把全部站点相加或把不完整记录按覆盖率放大。
- 地图覆盖全部年月。区划颜色来自区内站点均值，无支持区域留灰；不生成连续插值雨量。
- 月份季节曲线对可用年份等权；降雨频率和日内结果按观测数加权。日尾部仅保留合格月份内覆盖≥95%的站点日，分位数包含无雨日，有雨日定义为累计>0。
- 80/90/95%敏感性比较实际雨量结果。新结果不是原四站四个月结果的扩充命名，而是一套明确变更后的样本设计。

真实结果与独立检查保存在 `outputs/steps/task1-v5`；合并报告在 `report/project_report.pdf`，中文逐图解读在 `report/task1/` 与 `report/task2/`。旧方案已清理。未支持的年月不是零雨；八年描述性结果不能证明长期气候变化或具体天气成因。

## 4. 任务 2：时间标签与特征防泄漏

### 4.1 标签必须是连续六个真实未来格点

在 `t` 发出预测时，标签只相加 `t+5, t+10, …, t+30` 的六条观测。必须确认是六个**对应时间**，而不是接下来的六条记录；停测一小时后出现的记录不能作为接下来半小时的雨量。六个格点中任一个缺失，该训练/评估样本就不使用。累计目标取到 0.001 mm，减少二进制浮点求和使“恰好 5 mm”误判为严格大于 5 的风险。

每个标签的末尾时间不得越过所属时间划分的末尾。因此训练、验证、校准和测试边界附近最多 30 分钟的预测起点会被剔除。过去的可用历史可以来自上一年，这是合法信息；未来目标不能跨入下一份评估期间。

### 4.2 输入只能使用预测时已经获得的记录

默认保留 **10 分钟信息延迟**，使用 `t−10` 到 `t−65`（每 5 分钟一个，共 12 个）的历史格点。每条历史观测的两个来源更新时间都必须满足信息可用性规则，且不晚于 `t`；任一需要的历史格点不可用就不评分。这个规则把模拟预测与“事后观察整张数据表”区分开来。

这里的一小时累计指可用历史窗口中的 12 个格点，不包含截至 `t` 的最后 10 分钟。计算 15/30/60 分钟历史指标时，必须在方法说明中说明这一延迟定义，避免读者误以为用到了实时已经完成的最新雨量。两个更新时间是归档文件保留的时间信息，可能是后来的修订时间；没有逐版本发布历史，因而这个筛查是保守的信息可用性近似，不能证明完全复原了当时的数据流。

### 4.3 特征选择及科学理由

| 特征组 | 示例 | 理由 |
|---|---|---|
| 站点 | station ID 的训练期类别编码 | 不同地点暴露条件和局地雨型不同 |
| 地理位置 | 纬度、经度（来自当时观测） | 提供空间位置，减少只记住站号的局限 |
| 日周期 | 小时的 sine/cosine | 23:55 和 00:00 接近，整数小时不能表达这种循环 |
| 年周期 | 年内日期或月份的 sine/cosine | 表示季节相位，并保持年末与年初相邻 |
| 最近降雨 | `rain_lag_1/2/3`，分别为 `t−10/15/20` 分钟的雨量 | 持续性是半小时短临预报的重要信号 |
| 历史汇总 | `rain_sum_15/30/60`、`rain_max_30`、`wet_count_60`、`dry_fraction_60` | 表示强度、持续时间和雨势发展；全部窗口截止于 `t−10` |
| 变化量 | `rain_trend_15` = 最新三个格点累计 − 前三个格点累计 | 区分正在增强和减弱的降雨 |

经纬度、站名来自最新可用历史观测，不从未来元数据回填。**不使用**未来累计雨量、未来观测、未来更新时间、跨全八年计算的目标均值，或预测时尚不可能知道的当日总降雨。年份不直接作为连续线性外推特征；时间划分用于检验跨年泛化。StationIndexer 只在训练集拟合，对未见站点采用明确的 unknown 类别；数值 Imputer 的中位数也只在训练集拟合，它不能替代缺失的雨量历史或标签。坐标不能消除冷启动风险，应独立标记未见站点。

## 5. 为什么采用分布预测，而不是给每个阈值单独训练

如果分别为 1、2、5、10 mm 训练二分类器，容易出现 `P(Y>10) > P(Y>5)` 的自相矛盾，而且用户不能自由输入 3.7 mm。因此主模型用 Spark MLlib 的多分类随机森林预测未来 30 分钟雨量落在以下七个区间的概率：[3]

`{0}, (0,1], (1,2], (2,5], (5,10], (10,20], (20,+∞)`。

对用户阈值 `q`，计算

\[
\widehat P(Y>q\mid x)=\sum_{k=0}^{6}\widehat p_k(x)\widehat S_k(q),\qquad
\widehat S_k(q)=\frac{\#\{Y_i>q:Y_i\in B_k,\ i\in\text{train}\}}{\#\{Y_i\in B_k,\ i\in\text{train}\}}.
\]

即先预测各雨量区间概率，再乘上**只由训练期目标构造**的区间内经验超过率。它可以响应任意非负阈值，范围始终在 `[0,1]`，并且随阈值增加单调不增；在 0、1、2、5、10、20 这些边界，超过率直接对应更高区间的概率质量。

这不是完美的连续分布模型。对同一区间内更细的差异，所有站点和时间共享训练期形状；高于训练最大雨量时经验超过率为零，表示**训练支持范围限制，不是物理不可能**。界面或推理输出应标记这种情况。可以在进一步工作中比较更细分箱、分布回归或尾部模型，但本次结果不得声称已完成这些扩展。

随机森林适合非线性、交互关系和不同尺度数值变量，不需要标准化所有雨量值。站号是类别变量而非有顺序的实数；Spark 的类别元数据及足够的 `maxBins` 很重要。模型使用原始样本分布或均匀抽样，不默认对“有雨”过采样，以免把概率基准率改变后又误当作真实概率。

## 6. 时间划分、模型选择与概率校准

| 用途 | 年份 | 允许做什么 |
|---|---|---|
| 训练 | 2017–2021 | 拟合特征处理、随机森林、经验区间内分布和基线 |
| 验证 | 2022 | 比较候选超参数和确定决策阈值 |
| 校准 | 2023 | 仅选择温度校准参数 |
| 最终测试 | 2024 | 固定全部设计后评估一次，不再调参 |

随机切分会让相距五分钟、共享大量未来标签和过去特征的样本落在训练与测试两边，从而夸大效果。本项目用严格时间顺序划分，评估真实的向下一年迁移能力。

初始随机森林候选使用 40 棵树，深度 5 与 8；以验证集上多个阈值的平均 Brier score 选择，而不是凭准确率。计算资源不足时，训练和校准允许使用可复现的均匀样本，必须在 metadata 和实验记录注明比例、随机种子和各阶段样本数。全量 EDA 不应因为模型训练抽样而变成抽样 EDA；最终测试若也使用抽样，不能称为“完整 2024 测试”。

随机森林概率未必校准。保持选定模型不变，在 2023 年选择单一温度 `T`，使用

\[
p'_k=\frac{p_k^{1/T}}{\sum_jp_j^{1/T}}.
\]

候选为 `0.5, 0.75, 1, 1.25, 1.5, 2`，比较多个阈值平均 Brier。`T=1` 保持原概率，原有零概率仍为零；校准只调整区间质量，不破坏超过概率随阈值的单调性。确定温度后，将最终变换应用回 2022 验证数据，在对应概率尺度上选告警 cutoff；这份重新计算的验证表是调参资料，不是独立测试。2023 年不用于重新挑选特征或树深，也不读取 2024 指标决定是否保留校准。校准候选效果由 2023 表展示，最终测试只评价已选定的校准模型和预设基线。

## 7. 如何证明模型有用

最终测试比较：

- **站点—月份—小时气候基线**：训练期相同条件下的经验分布，小样本组合使用平滑/回退；检验季节与地点信息本身能做到什么。
- **随机森林校准概率**：检验单独年份校准是否提高概率可信度。

原始随机森林候选的比较发生在 2022 模型选择表；温度（包括不调整的 T=1）比较发生在 2023 校准表，不额外承诺第三份未经运行的最终测试结果。最终指标中的模型名 `random_forest` 指已经使用所选温度变换的随机森林。

默认阈值为 **0、0.2、1、2、5、10、20 mm**。主要指标：

| 指标 | 用途 | 解读注意 |
|---|---|---|
| Brier score | 概率均方误差；越低越好 | 与同一数据上的基线比较；单看数值小不代表有用 |
| Brier skill score | `1 − BS_model / BS_baseline` | 正值优于基线；基线误差为 0 时无定义 |
| Log loss | 惩罚过度自信的错误 | 计算时仅为数值稳定截断到很小的 epsilon |
| PR-AUC | 罕见超过事件的区分能力 | 必须同时给出 prevalence；不同阈值基础难度不同 |
| ROC-AUC | 一般排序能力 | 稀有事件时可能显得乐观，不能单独作为结论 |
| Precision / Recall / F1 | 指定告警 cutoff 下的表现 | cutoff 从验证集确定，禁止在测试集上追求最好 F1 |
| 可靠性曲线 | 预测概率与真实频率的一致性 | 同时列各概率箱样本量；高雨量箱样本少时波动大 |

当某个阈值在测试子集中只有单一类别，ROC/PR 指标无定义，应显示缺失而不是伪造为 1 或 0。绘图器不把缺少模型结果的空图当成“实验完成”。

重叠的半小时窗口和空间相关雨站违反独立样本假设，因此不要使用独立 Bernoulli 标准误给出极窄区间。训练脚本保存每天成对的模型/基线误差和样本数，可供以后进行考虑时间依赖的不确定性分析；当前独立绘图代码不计算 bootstrap 区间。

## 8. Google Cloud 计算环境记录

建议初始配置：Dataproc `2.2.87-debian12`，Spark `3.5.3`；一个 `e2-standard-4` 主节点，两个 `e2-standard-8` 工作节点；每个节点 100 GB 磁盘；GCS 保存原始数据、Parquet、中间结果和模型；区域建议 `asia-southeast1`。名义总量是 **20 vCPU、80 GB 内存**，其中工作节点为 16 vCPU、64 GB，主节点并非全部算力都给 executor。[4]

这是**计划配置**。实验记录必须使用实际 `gcloud dataproc clusters describe`、Spark 运行日志和保存的 metadata：包括实际 image、Spark/Python/Java 版本、节点类型/数目、磁盘、Spark 参数、分区数、随机种子、训练抽样比例、各阶段运行时间与是否发生重试。若使用不同镜像或机器，应更新记录，不能直接把计划配置写成已运行。

CSV 仅供原始输入；清洗后用 Parquet 减少扫描和解析成本。聚合、连接、窗口、特征生成、训练和评估由 Spark 完成。Pandas/Matplotlib 只读取 Spark 输出的小型汇总表画图，不能把八年原始数据 `toPandas()` 到 driver。避免为了画图把全部日表/预测表下载到本地；绘图只需聚合输出。
